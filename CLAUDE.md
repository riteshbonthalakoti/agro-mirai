# AGRO MIRAI — Project Rules for Claude Code

All subagents inherit these rules automatically.

## Stack
- Backend: Python 3.12 + FastAPI (`src/agro_mirai/`)
- Mobile: React Native 0.86 + Expo SDK 57 + TypeScript (`mobile/`)
- DB: Supabase PostgreSQL (prod) + SQLite (offline fallback)
- AI/Voice: Sarvam AI (`saaras:v2` STT, `bulbul:v1` TTS)

## Hard Rules

### Never break these
1. **account_id isolation** — every DB query scoped to calling user's account. No exceptions.
2. **API response shapes** — field names are mobile app contracts. Rename = breaking change.
3. **SMS_APP_HASH** in `.env` — do NOT modify `src/agro_mirai/auth/otp_providers.py` hash logic.
4. **MEM_CACHE in hooks.ts** — zero-flicker tab switching depends on this. Don't touch.
5. **AnimatedSplashScreen.tsx 2250ms timer** — release-tuned. Leave alone.
6. **DEVICE_GLOBAL_KEYS in storage.ts** — notification persistence keys. Don't remove entries.
7. **Database migrations** — never edit files in `supabase/migrations/` or `migrations/sqlite/`. Add new files only.

### Code style
- Python: async/await everywhere, Pydantic v2 models for all request/response bodies, type hints required
- TypeScript: strict mode, no `any`, use theme tokens from `theme.ts` never hardcoded colors
- No AI-generated commit trailers (no "Generated by Claude" in commits)
- Commits: conventional format `type(scope): message`

### Test commands
```bash
# Backend
.venv\Scripts\pytest.exe -q tests/auth/ tests/api/

# Mobile typecheck
cd mobile && npx tsc --noEmit

# Release APK
cd mobile/android && ./gradlew assembleRelease
```

### Refactoring doctrine
- One file per commit
- Run tests after every change
- Read-only planning before any edits (use code-explorer agent first)
- Preserve all public function signatures and exported types
- Delete dead code only after confirming 0 usages via Grep
