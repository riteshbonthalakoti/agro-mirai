# DEMO_SCRIPT.md — 10-minute live review walkthrough

Read `docs/DEMO_DAY.md` first and wake the deployed instance up 5-10
minutes before you start. Two things this project claims that a
generic capstone doesn't — lead with them: **(1)** a full
data→model→explanation→advisory pipeline, not just a model in a
notebook, and **(2)** a real Kannada voice story, not a translated
label. Everything below budgets for a 10-minute slot; cut the "if time
allows" bits first if you're running long.

---

## 0. Open with the one-sentence pitch (30s)

> "AGRO MIRAI takes a farmer's field, pulls real weather/soil/satellite
> data, and gives three concrete recommendations — crop, irrigation,
> disease risk — each with a plain-language explanation, in Kannada."

## 1. The deployed app — dashboard (1 min)

Open the deployed URL (from `docs/DEMO_DAY.md`) — **not** localhost,
so the evaluator sees it's actually hosted, not just running on your
laptop. Show:
- The dashboard: "Welcome, Ravi Kumar", the hero stat strip, the "North
  Plot" field card.
- Say: "This is server-rendered Flask, calling this same project's own
  JSON API — no separate frontend service to deploy."

## 2. Field detail — the full pipeline (3 min)

Click into **North Plot**. This is the main event — walk through each
card and say what module produced it:

1. **Crop recommendation** — "RandomForest trained on the Kaggle
   crop-recommendation dataset, 99.5% held-out accuracy." Point at the
   recommended crop.
2. **Irrigation advice** — urgency + recommended depth. Mention the
   urgency is a trained classifier; the depth-mm number is a documented
   rule-based lookup (no dataset had a continuous depth target — say
   this plainly, it's a strength that it's documented, not hidden).
3. **Disease risk** — point at the severity badge and its distinct icon
   shape (not just color — colorblind-safe by design). Mention this one
   is a transparent weighted-scoring formula, not a black-box model,
   because no labeled disease dataset existed for this project's scope.
4. **The explanation text under each** — "This is SHAP for the two
   trained models, and the exact weight breakdown for the disease-risk
   score — same interface either way, so the UI never has to know which
   kind of model produced it."

## 3. The Kannada voice story (2-3 min) — the second differentiator

Pick one, depending on where you are:

**A. Live, on your own machine** (best option — do this if you can be
at your laptop with the `.venv` ready beforehand):
```bash
.venv\Scripts\activate
python
```
```python
import sys; sys.path.insert(0, "src")
from agro_mirai.voice.ai4bharat_voice import AI4BharatVoiceService
svc = AI4BharatVoiceService()
kn = svc.translate("Your soil moisture is low. Irrigate today.", "en", "kn")
print(kn)
audio = svc.text_to_speech(kn, "kn")
open("kn_output.wav", "wb").write(audio)
```
Play `kn_output.wav`. Say: "That's a real IndicTrans2 translation and
real Piper/AI4Bharat TTS running on this laptop, no internet
dependency, no pre-scripted audio."

**B. Fallback — pre-recorded clip.** If you're not near your own
machine (presenting from a lab PC, projector-only setup, etc.), have a
`kn_output.wav` already generated and saved on a USB drive / uploaded
somewhere you can play from. Say the same thing, but be upfront: "This
clip was generated by the same pipeline ahead of time — the interface
is real, running it live just isn't practical from this machine."
**Never claim a pre-recorded clip is live** if asked directly.

Mention why this isn't on the hosted Render instance: 512MB free tier,
~6.8GB of model weights — a deliberate, documented scope call
(`decisions/0014-deploy-target-and-voice-scope.md`), not an oversight.

## 4. Feedback loop (1 min)

Scroll to the feedback form on the field-detail page, pick a star
rating, submit. Show the "Thanks — your feedback was recorded"
confirmation. If time allows, run
`python tools/feedback_report.py --seed` in a terminal to show the
aggregation side (counts, average rating, helpful rate) without
needing to have submitted many entries live.

## 5. The raw API (1 min, if time allows)

One or two `curl` calls straight from `MANUAL_TEST_GUIDE.md` §5 against
the deployed URL — `/health`, `/fields/{id}/advisories` — to show real
JSON, and one deliberate 401 (wrong key) to show auth actually rejects.

## 6. Close (30s)

> "Fifteen modules, each gated on the last being tested and committed,
> every non-obvious decision written down in `decisions/` as it was
> made — not reconstructed afterward for the report."

## If something breaks live

- **Cold-start hang on first request** — you forgot to wake it up
  (`docs/DEMO_DAY.md`). Say so, wait it out, or switch to a screenshot/
  screen-recording as backup while it warms up.
- **A 500 you've never seen before** — don't debug live. Say "that's a
  real bug, not something I'll paper over" and move to the next section;
  note it down and fix it after.
- **Supabase paused** — `/health` will say `"degraded"`. That's a
  legitimate thing to point at (the repository interface degrading
  gracefully) rather than a crash — but restore it beforehand if you can
  (see `docs/DEMO_DAY.md`).
